# GPXFixer

Kotlin Multiplatform приложение для работы с треками активностей в форматах
**GPX** и **FIT**: импорт, просмотр с графиками, редактирование, экспорт, а также
**запись собственных треков** по GPS с Bluetooth-датчиками мощности и пульса.

Проект умеет выбирать GPX- или FIT-файл на Android и iOS, разбирать его в общей
KMP-логике в единую модель `ActivityDocument`, сохранять исходник, вести локальную
историю треков, показывать трек на карте и графиках (мощность, пульс, скорость),
обрезать трек, удалять и перемещать точки, переименовывать и удалять треки и
экспортировать результат обратно в GPX или FIT. Для FIT экспорт по возможности
**патчит исходные байты**, сохраняя всю несмоделированную информацию (сенсоры,
session/lap, developer/unknown-сообщения).

## Текущий стек

- Kotlin Multiplatform
- Compose Multiplatform (Android UI), SwiftUI (iOS UI)
- [Kable](https://github.com/JuulLabs/kable) — кроссплатформенный BLE
- Google Maps Compose (Android), Apple MapKit (iOS)
- Gradle Kotlin DSL

## Модули

- `shared` — общий KMP-модуль: доменные модели GPX и `ActivityDocument`,
  GPX parser/serializer, чистый Kotlin FIT decoder/encoder/raw-patcher, мапперы
  форматов, use case'ы импорта, просмотра, редактирования, экспорта, записи трека,
  BLE-датчики (мощность, пульс), профиль пользователя, расчёт графиков,
  iOS facade и тесты.
- `app-android` — Android-приложение: импорт, список треков, просмотр с картой и
  графиками, trim/edit flow, экспорт, экран записи с foreground-сервисом,
  экраны пейринга датчиков, профиль, top app bar навигация.
- `iosApp` — iOS-приложение на SwiftUI с тем же набором экранов: импорт, история,
  просмотр с графиками, trim/edit, экспорт/шаринг, запись, датчики, профиль.

## Общая модель и форматы

- `ActivityDocument` — единая доменная модель (metadata, треки, сегменты, точки с
  координатами, высотой, временем, ЧСС, мощностью, каденсом, дистанцией, скоростью).
  Редактор, просмотр и запись работают только с ней, независимо от формата.
- `ActivityGpxMapper` / `ActivityFitMapper` — конвертация GPX/FIT в `ActivityDocument`.
- Каждая точка хранит `sourceIndex` — ссылку на исходное FIT `record`-сообщение,
  которая переживает редактирование и нужна для точечного патча при экспорте.

### GPX

- GPX parser с поддержкой namespace, escaped text, CDATA и self-closing tags.
- GPX serializer для обратной записи документа в XML.

### FIT (чистый Kotlin, без внешних зависимостей)

- `FitActivityDecoder` — разбор бинарного FIT: заголовок, сигнатура, header/file CRC,
  definition/data-сообщения, compressed-timestamp, таблица base types, отсев
  invalid-значений, little/big-endian; маппинг `record`/`session`/`sport`/`file_id`
  в модель.
- `FitEncoder` — сборка полноценного FIT-activity из `ActivityDocument`:
  `file_id`, timer-`event`'ы вокруг `record`-потока (start/stop на каждый сегмент,
  так что паузы записи сохраняются), `lap`, `session` с агрегатами и завершающий
  `activity` с UTC/local-временем — структура, которую принимают Strava и
  подобные сервисы.
- `FitRawPatcher` — редактирование FIT на уровне сырых сообщений: удалённые
  `record`-сообщения выкидываются, у перемещённых переписываются координаты, а все
  прочие сообщения (file_id, session, lap, device_info, sensors, developer/unknown)
  копируются байт-в-байт; пересчитываются dataSize и CRC.
- `FitCrc` — CRC-16 протокола FIT.

## Use cases (общие)

- `ImportGpxTrackUseCase` — валидирует GPX, выбирает display name, сохраняет исходник
  и metadata импорта, откатывает файл при ошибке записи metadata.
- `ImportFitTrackUseCase` — декодирует FIT, требует наличия GPS-точек, сохраняет
  результат как `ActivityDocument` и **оригинальные байты FIT** (base64-сайдкар) для
  последующего патча, откатывает при ошибке.
- `TrackDetailUseCase` — загружает трек, считает summary (дистанция, набор/сброс
  высот, время, предупреждения по неполным данным).
- `TrackChartCalculator` / `TrackChartPresenter` — метрико-нейтральный расчёт
  графиков мощности/пульса/скорости для экрана трека.
- `TrimGpxTrackUseCase`, `DeleteGpxTrackPointUseCase`, `MoveGpxTrackPointUseCase` —
  обрезка и точечное редактирование с валидацией и пересчётом summary.
- `ExportFitTrackUseCase` — если есть сохранённый оригинал FIT, патчит его
  (`FitRawPatcher`), иначе кодирует документ с нуля (`FitEncoder`).
- `RenameTrackUseCase` — переименование трека.
- `DeleteImportedTrackUseCase` — удаление трека вместе с исходником и FIT-сайдкаром.
- `SaveRecordedTrackUseCase` — сохранение записанного трека в общую историю.

## Запись трека

- `TrackRecorder` — чистая state machine без платформенных зависимостей
  (детерминирована в тестах): принимает `LocationSample`'ы и сэмплы датчиков,
  ведёт дистанцию/время/скорость; каждый цикл pause/resume открывает новый
  сегмент, паузы не входят в дистанцию и активное время.
- `LocationSource` — платформенный источник GPS (Android/iOS реализации).
- На Android запись идёт в **foreground service**; разрешения на локацию и BLE
  запрашиваются по мере необходимости.
- `RecordingJournal` — crash-safe журнал: запись переживает убийство процесса.
- Экран записи показывает **live-карту маршрута** и **live-график мощности**
  на фиксированной временной шкале.

## BLE-датчики

- Датчик **мощности** (Cycling Power Measurement) и датчик **пульса**
  (Heart Rate Measurement): парсеры пакетов, транспорт на Kable,
  экраны пейринга на обеих платформах.
- Выбранные датчики сохраняются и **автоматически переподключаются** при обрывах
  во время записи (`PowerSensorReconnectManager`, `HeartRateSensorReconnectManager`).
- Данные датчиков вливаются в записываемые точки (`power`, `heartRate`).

## Профиль пользователя

- `UserProfile`: вес, пол, год рождения, FTP, зоны пульса (5 зон) и зоны мощности
  (7 зон по Коггану). Все поля опциональны — фичи, которым нужен профиль, скрыты,
  пока он не заполнен.
- Дефолтные зоны считаются из возраста/FTP (`ZoneDefaults`), ввод валидируется
  (`ProfileValidation`).
- Хранение — общий `UserProfileRepository` (JSON-файл), один на обе платформы;
  экран профиля есть на Android и iOS.

## Платформы

Оба приложения предоставляют один и тот же пользовательский поток:

- выбор GPX/FIT через системный document picker и импорт по `ACTION_VIEW` (Android)
  или `.onOpenURL` (iOS); регистрация типов `.gpx`/`.fit` для «Открыть с помощью»;
- локальное хранение исходников и JSON-история треков;
- список треков и экран деталей с картой и графиками мощности/пульса/скорости;
- полноэкранный интерактивный график с зумом и пан-слайдером;
- обрезка трека с предпросмотром summary и сохранением поверх трека;
- редактирование на полноэкранной карте: выбор ближайшей точки, отдельные точки
  на крупном масштабе, стрелки для точного перемещения и перехода между точками,
  timestamp точки в меню, удаление с отменой, сохранение поверх трека;
- переименование и удаление треков;
- экспорт двумя кнопками — **Export GPX** и **Export FIT** — через share sheet;
- запись трека с live-картой и live-графиком мощности, пейринг датчиков, профиль.

iOS-реализации storage/store/id/clock, BLE и recording-фасады лежат в
`shared/src/iosMain`.

## Экспорт и сохранность информации

- Экспорт форматно-независим: из любого трека можно получить GPX или FIT.
- **FIT → FIT** импортированного трека сохраняет всю информацию: при экспорте мы
  патчим исходные байты, а не пересобираем файл.
- **FIT → GPX** теряет данные сенсоров (ЧСС/мощность/каденс/скорость) — в стандартном
  GPX для них нет полей (расширения `gpxtpx` пока не поддержаны).
- **GPX → FIT**, записанные треки и треки без сохранённого оригинала идут через
  `FitEncoder`.

## Google Maps API key для Android

Android-карта использует Maps SDK for Android через Google Maps Compose. Ключ не
коммитится: добавьте его локально в `local.properties` в корне проекта:

```properties
MAPS_API_KEY=your_api_key_here
```

Получить ключ можно в Google Cloud Console:

1. Создать или выбрать Google Cloud project.
2. Включить `Maps SDK for Android`.
3. Создать API key в разделе `APIs & Services` -> `Credentials`.
4. Ограничить ключ для Android-приложения `com.gpxeditor.android` и подписывающего
   сертификата SHA-1.

## Известные ограничения

- При удалении точек через FIT-патч агрегаты `session`/`lap` (total_distance,
  число записей и т.п.) сохраняются как в оригинале и **не пересчитываются**.
- Удаление `record` с полным timestamp сдвигает подразумеваемое время последующих
  compressed-timestamp записей (редкость в activity-файлах).
- Зоны пульса/мощности из профиля пока нигде не используются (нет времени в зонах
  и раскраски графиков).
- Нет авто-паузы при записи.

## Что намеренно НЕ реализовано

- Редактируемая карта (свободное рисование)
- Split/merge сегментов
- Полная undo/история изменений (есть только отмена удаления точки)
- Сохранение отредактированного трека как отдельной копии
- Сглаживание высоты
- Backend и сетевой слой
- DI-фреймворк
- Навигационная библиотека
- Локальная БД вместо JSON-файлов

## Ближайшие логичные шаги

- Разбить экран записи на табы (карта / мощность / пульс) — issues #64, #65.
- Авто-пауза записи — issue #41.
- Применить зоны из профиля: время в зонах на экране трека, раскраска графиков,
  текущая зона на экране записи.
- Экспорт GPX с расширениями `gpxtpx` (пульс/мощность/каденс), чтобы FIT → GPX
  не терял сенсорные данные.
- Пересчитывать агрегаты `session`/`lap` после редактирования FIT.
- Сглаживание графиков: средняя линия + конверт min/max вместо min-max заливки.
