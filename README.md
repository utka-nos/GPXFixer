# GPXFixer

Kotlin Multiplatform приложение для импорта, просмотра, редактирования и экспорта
треков в форматах **GPX** и **FIT**.

Проект умеет выбирать GPX- или FIT-файл на Android и iOS, разбирать его в общей
KMP-логике в единую модель `ActivityDocument`, сохранять исходник, вести локальную
историю импортированных треков, показывать трек на карте, обрезать трек по
началу/концу, удалять и перемещать точки и экспортировать результат обратно в GPX
или FIT. Для FIT экспорт по возможности **патчит исходные байты**, сохраняя всю
несмоделированную информацию (сенсоры, session/lap, developer/unknown-сообщения).

## Текущий стек

- Kotlin Multiplatform
- Compose Multiplatform
- Android + iOS targets
- Gradle Kotlin DSL

## Модули

- `shared` — общий KMP-модуль: доменные модели GPX и `ActivityDocument`,
  GPX parser/serializer, чистый Kotlin FIT decoder/encoder/raw-patcher, мапперы
  форматов, use case импорта (GPX/FIT), просмотра, обрезки, удаления и перемещения
  точек, экспорта FIT, iOS facade и тесты.
- `app-android` — Android-приложение с выбором GPX/FIT, импортом, локальным
  хранением исходников, списком импортированных треков, просмотром, trim/edit flow
  и экспортом в GPX или FIT.
- `iosApp` — iOS-приложение на SwiftUI с выбором GPX/FIT, импортом, локальной
  историей треков, просмотром, trim/edit flow и шарингом GPX/FIT.

## Общая модель и форматы

- `ActivityDocument` — единая доменная модель (metadata, треки, сегменты, точки с
  координатами, высотой, временем, ЧСС, мощностью, каденсом, дистанцией, скоростью).
  Редактор и просмотр работают только с ней, независимо от исходного формата.
- `ActivityGpxMapper` / `ActivityFitMapper` — конвертация GPX/FIT в `ActivityDocument`.
- Каждая точка хранит `sourceIndex` — ссылку на исходное FIT `record`-сообщение,
  которая переживает редактирование и нужна для точечного патча при экспорте.

### GPX

- GPX parser с поддержкой namespace, escaped text, CDATA и self-closing tags.
- GPX serializer для обратной записи документа в XML.

### FIT (чистый Kotlin, без внешних зависимостей)

- `FitActivityDecoder` — разбор бинарного FIT: заголовок, сигнатура, header/file CRC,
  definition/data-сообщения, compressed-timestamp, таблица base types, отсев
  invalid-значений, little/big-endian; маппинг `record`/`session`/`sport`/`file_id`
  в модель.
- `FitEncoder` — сборка FIT из `ActivityDocument` (`file_id` + `record`-сообщения).
- `FitRawPatcher` — редактирование FIT на уровне сырых сообщений: удалённые
  `record`-сообщения выкидываются, у перемещённых переписываются координаты, а все
  прочие сообщения (file_id, session, lap, device_info, sensors, developer/unknown)
  копируются байт-в-байт; пересчитываются dataSize и CRC.
- `FitCrc` — CRC-16 протокола FIT.

## Use cases (общие)

- `ImportGpxTrackUseCase` — валидирует GPX, выбирает display name, сохраняет исходник
  и metadata импорта, откатывает файл при ошибке записи metadata.
- `ImportFitTrackUseCase` — декодирует FIT, требует наличия GPS-точек, сохраняет
  результат как `ActivityDocument` и **оригинальные байты FIT** (base64-сайдкар) для
  последующего патча, откатывает при ошибке.
- `TrackDetailUseCase` — загружает сохранённый трек, считает количество треков/
  сегментов/точек, дистанцию, набор/сброс и диапазон высот, старт/финиш, временной
  диапазон и предупреждения по неполным данным.
- `TrimGpxTrackUseCase` — обрезает документ по диапазону точек, чистит пустые
  элементы, пересчитывает summary.
- `DeleteGpxTrackPointUseCase` — удаляет точку по индексу, чистит пустые элементы.
- `MoveGpxTrackPointUseCase` — перемещает точку в новые координаты с валидацией.
- `ExportFitTrackUseCase` — если есть сохранённый оригинал FIT, патчит его
  (`FitRawPatcher`), иначе кодирует документ с нуля (`FitEncoder`).

## Платформы

Оба приложения предоставляют один и тот же пользовательский поток:

- выбор GPX/FIT через системный document picker и импорт по `ACTION_VIEW` (Android)
  или `.onOpenURL` (iOS);
- регистрация типов документов на `.gpx` и `.fit`, чтобы система предлагала
  приложение в «Открыть с помощью»;
- локальное хранение исходников и JSON-история импортов;
- список импортированных треков и экран деталей;
- просмотр линии трека (Google Maps на Android, Apple MapKit на iOS) и полноэкранная
  карта;
- обрезка трека с предпросмотром summary и сохранением поверх трека;
- редактирование на полноэкранной карте: выбор ближайшей точки, удаление и
  перемещение точки, сохранение поверх трека;
- экспорт двумя кнопками — **Export GPX** и **Export FIT** (доступны для любого
  трека) — через системный share sheet.

iOS-реализации storage/store/id/clock и `IosImportFacade` лежат в `shared/src/iosMain`.

## Экспорт и сохранность информации

- Экспорт форматно-независим: из любого трека можно получить GPX или FIT.
- **FIT → FIT** импортированного трека сохраняет всю информацию: при экспорте мы
  патчим исходные байты, а не пересобираем файл.
- **FIT → GPX** теряет данные сенсоров (ЧСС/мощность/каденс/скорость) — в стандартном
  GPX для них нет полей.
- **GPX → FIT** и экспорт треков без сохранённого оригинала идут через `FitEncoder`.

## Google Maps API key для Android

Android-карта использует Maps SDK for Android через Google Maps Compose. Ключ не
коммитится: добавьте его локально в `local.properties` в корне проекта:

```properties
MAPS_API_KEY=your_api_key_here
```

Получить ключ можно в Google Cloud Console:

1. Создать или выбрать Google Cloud project.
2. Включить `Maps SDK for Android`.
3. Создать API key в разделе `APIs & Services` -> `Credentials`.
4. Ограничить ключ для Android-приложения `com.gpxeditor.android` и подписывающего
   сертификата SHA-1.

## Известные ограничения

- `FitEncoder` собирает минимальный FIT (`file_id` + `record`), без `session`/`lap`/
  `activity`. Такой файл валиден по структуре, но некоторые сервисы (например, Strava)
  не финализируют активность без `session`/`activity`. Импортированные FIT-треки
  экспортируются через патч оригинала и этим не затронуты; ограничение касается
  fallback-пути (GPX → FIT и треки без сохранённого оригинала).
- При удалении точек агрегаты `session`/`lap` (total_distance, число записей и т.п.)
  сохраняются как в оригинале и **не пересчитываются**.
- Удаление `record` с полным timestamp сдвигает подразумеваемое время последующих
  compressed-timestamp записей (редкость в activity-файлах).
- Сайдкар с оригиналом FIT не удаляется при удалении трека.

## Что намеренно НЕ реализовано

- Редактируемая карта (свободное рисование)
- Split/merge сегментов
- Undo/history изменений
- Сохранение отредактированного трека как отдельной копии
- Сглаживание высоты
- Переименование трека
- Backend
- DI
- Навигация
- Локальная БД вместо JSON-файлов
- Сетевой слой

## Ближайший логичный следующий шаг

  fallback- и GPX → FIT-экспорт принимались Strava и подобными сервисами.
- Пересчитывать агрегаты `session`/`lap` после редактирования.
- Добавить undo/reset для текущей edit-сессии и удаление диапазона точек.
- Прогнать кейсы multi-track/multi-segment, одна точка, отсутствующие высота/время,
